HARI ACTIVE DIRECTION

The Android assistant path is frozen. The active experiment is a fixed-resource continual learner.

Rules of the experiment:

- no pretrained language model inside HARI
- no transformer requirement
- no GPU requirement for normal learning
- no global retraining after each experience
- fixed memory/resource budgets
- knowledge must change online
- uncertainty must be explicit
- corrections must not require replaying the whole lifetime
- repeated experience should compress into reusable structure
- state must survive restart
- every claimed capability needs a held-out or adversarial test

The current MVP is under hari/life/.

Its internal pieces are:
- bounded episodic memory
- decaying local token/meaning association memory
- learned action-role schemas
- induced outcome programs
- mutable fact memory
- prediction error / surprise
- explicit ASK vs ACT behavior
- persistence and inspectable evidence traces

This is not a claim of human intelligence. It is a machine for testing whether useful capability can accumulate under a fixed physical budget.

Kill condition:
If harder grounded worlds show that capability only improves by increasing state/compute roughly in proportion to experience, or if composition collapses outside hand-shaped representations, we change or kill the architecture instead of hiding the failure with more compute.
